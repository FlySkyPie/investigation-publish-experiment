如何安裝 Kairos 並設定 k3s：完整實作指南#

摘要#

Kairos 是一套開源的「不可變（immutable）Linux 元發行版（meta-distribution）」，目標是讓邊緣（edge）、雲端與裸機節點的作業系統生命週期能以 Kubernetes 原生方式管理1。它被 CNCF（Cloud Native Computing Foundation）接納為 Sandbox 專案，接納日期為 2024-04-132。Kairos 的預設發行版（flavor）是 Hadron，這是一套由 Kairos 團隊從零打造、以 musl libc 搭配 systemd 的精簡 Linux 基底34。

本報告以「實作」為核心：說明如何取得 Kairos ISO、寫入 USB、完成安裝，並用 cloud-config 啟用 k3s（或 k3s-agent）以建立單節點、多節點與高可用（HA）叢集，最後涵蓋安裝後設定、升級、取用 kubeconfig 與疑難排解。本報告同時保留來源間的差異（例如互動式安裝產生的設定檔名），並在文末做批判性來源反思。

本報告的事實以 2026-10-18 的檢索結果為準。Kairos 與 k3s 版本迭代頻繁，實作前請以官方最新文件與 release 頁面為準。

1. Kairos 是什麼#

1.1 定位與治理#

  • Kairos 自稱為「不可變 Linux 元發行版」，用於邊緣 Kubernetes2。
  • 它是 CNCF Sandbox 專案，於 2024-04-13 被接納2。
  • 授權條款為 Apache License 2.05。
  • 主要語言為 Go5。
  • 截至 2026-10-18 檢索，GitHub 專案 kairos-io/kairos 約有 1,855 顆星、153 個 fork5。

1.2 三個核心架構概念#

（一）不可變系統佈局。 安裝完成後，根目錄 / 為唯讀，安裝後無法再新增套件；/usr/local 與 /oem 為持久（persistent）分割區，會跨升級保留；/var、/etc、/srv 則為暫時（ephemeral），重開機後變更會被捨棄1。持久路徑會被 bind-mount 到 /usr/local/.state，預設包含 /etc/ssh、/etc/systemd、/etc/kubernetes、/home、/opt、/root、/var/lib/containerd、/var/lib/kubelet、/var/lib/etcd、/var/log 等1。

（二）A/B 原子升級（atomic upgrade）。 Kairos 採雙分割區 A/B 配置，並加上 recovery 備援。安裝時建立的分割區包含：state（存放 active 與 passive 開機用的容器映像，.img）、recovery（存放 .squashfs 映像）、選用的 OEM（使用者設定），以及 persistent（跨重開機保留資料）1。開機順序為 Active → Passive → Recovery；升級時會從容器登錄檔（container registry）拉取新映像、建立 transition 映像，下次重開機後 transition 成為 Active，舊 Active 變成 Passive；若開機失敗，bootloader 會自動回退1。

（三）元發行版（meta-distribution）。 Kairos 的設計目標是把其他 Linux 發行版「轉換」成具備不可變佈局與 Kubernetes 原生元件的系統1。核心元件（v4.3.0 起合併至 kairos-io/kairos 單一 repo）包含：kairos-init（在標準上游發行版上建構 Kairos 映像）、immucore（不可變管理介面）、agent（節點的安裝、重置、升級）、kcrypt（TPM + LUKS 靜態資料加密）、installer（互動式終端 UI 安裝器）、provider（k3s／k0s 與 P2P 支援）與 sdk1。

1.3 Hadron：預設發行版#

Hadron 是 Kairos 團隊從零打造的極精簡 Linux 發行版，官方部落格於 2025-12-17 發布介紹文3。其關鍵屬性：

  • libc：musl3（版本 1.2.6）4
  • init：systemd3（Hadron v0.5.3 為 systemd 261.3；v0.6.0 為 systemd 262）4
  • 套件管理器：刻意不提供（no package manager by design）3
  • 核心：vanilla Linux kernel（v0.5.3 為 7.2.6；v0.6.0 為 7.2.10）4
  • 開機：支援標準開機（Dracut/GRUB）與 Trusted Boot（UKI/USI）4
  • Hadron 被描述為「少數刻意同時結合 musl libc 與 systemd 的發行版」3

其他歷史發行版（Ubuntu、Rocky、openSUSE、Debian、Fedora、Alpine 等）仍可透過 kairos-init 自建，但官方 release pipeline 不再產製預建映像檔，預建產物以 Hadron 為主4。Hadron 於 2026-01-28 由 Spectro Cloud 發出正式新聞稿6。

2. 版本與映像檔選擇#

2.1 目前版本#

  • Kairos 最新穩定版：v4.3.0，於 2026-09-08 發布，是第一個從合併後 monorepo 釋出的版本7。
  • 該版本使用的 Hadron：v0.5.1（release 資產命名）17。
  • 已知釋出的三個 k3s 版本：v1.34.11+k3s1、v1.35.8+k3s1、v1.36.4+k3s1（最新為 v1.36.4+k3s1）7。

註：另有來源指出 Hadron v0.5.3（2026-09-18）與 Hadron v0.6.0（2026-10-14）已釋出4，但 Kairos v4.3.0 的官方 ISO 資產仍以 Hadron v0.5.1 命名7。此為上游 Hadron 與 Kairos 發布節奏不同步所致，實作時以 release 資產實際檔名為準。

4.1 裸機：下載、驗證、寫入 USB#

步驟 1：下載 ISO 及對應的 .sha256、.sha256.bundle 檔案8。

步驟 2（建議）：驗證簽章。 需要 sha256sum 與 cosign v2.0.0 以上12：

cosign verify-blob \
  --bundle kairos-hadron-v0.5.1-core-amd64-generic-v4.3.0.iso.sha256.bundle \
  --certificate-identity https://github.com/kairos-io/kairos/.github/workflows/reusable-factory.yaml@refs/tags/v4.3.0 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  kairos-hadron-v0.5.1-core-amd64-generic-v4.3.0.iso.sha256

sha256sum -c kairos-hadron-v0.5.1-core-amd64-generic-v4.3.0.iso.sha256

預期輸出 Verified OK 與 <iso>: OK12。

步驟 3：寫入 USB。

dd if=/path/to/kairos.iso of=/path/to/dev bs=4MB

或用 GUI 工具如 balenaEtcher11。

步驟 4：由 USB 開機，進入 GRUB 選單，選第三項 kairos (interactive install) 進行互動式安裝，或改用下列其他方法13。

4.2 互動式安裝（Interactive）#

  • 由 GRUB 選單選擇第三項 kairos (interactive install)13。

  • 或在 LiveCD 上手動執行：

    kairos-agent interactive-install

    13

  • 互動式安裝會產生一份設定檔，安裝後位於 /oem/90_custom.yaml13。

互動式安裝器（kairos-installer）依序詢問：磁碟（必填，確認訊息為「Everything on {value} will be erased.」）、使用者與密碼（密碼會先雜湊再寫入設定）、SSH 公鑰、主機名稱、時區與鍵盤、系統擴充套件、Provider 設定，以及安裝完成後的動作（Nothing / Reboot / Power off）13。其中 Provider 設定會依內建 provider plugin 顯示額外問題，預設 provider 會問「是否啟用 k3s？」與「是否啟用 k0s？」13。摘要畫面顯示產生的 #cloud-config，可按 e 編輯、按 v 檢視，按 Enter 後需輸入 y 確認才會抹除磁碟13。

來源不一致：互動式安裝頁面明確寫 /oem/90_custom.yaml13；而 after-install 頁面在描述 /oem 讀取順序時，提及互動式安裝器產生的是 /oem/99_custom.yaml14。兩種檔名都曾被文件提及，實作時建議以實際節點上 kairos-agent config 的輸出為準14。

4.3 手動安裝（Manual install with cloud-config）#

建立 cloud-config.yaml（第一行必須是 #cloud-config）：

#cloud-config

users:
- name: "kairos"
  passwd: "kairos"
  ssh_authorized_keys:
  - github:mudler
  - "ssh-rsa AAA..."

k3s:
  enabled: true

執行（具破壞性，會抹除磁碟）：

sudo kairos-agent manual-install --device "auto" cloud-config.yaml

--device "auto" 會自動選擇最大的磁碟；也可指定 /dev/sda 等裝置1516。

安全提醒：安裝後若未在 cloud-config 中提供 ssh_authorized_keys，可能無法以 SSH 登入（密碼登入會被停用）；passwd 主要用於實體主控台（tty）登入16。

4.4 WebUI 安裝#

LiveCD 開機後，Kairos 預設在 8080 埠啟動 WebUI。以瀏覽器開啟 http://<機器IP>:8080，貼上 cloud-config YAML，於 device 欄位輸入 auto，勾選「Restart after installation」後安裝1011。

4.5 全自動（零接觸）安裝#

方式 A：資料來源 ISO（data source ISO）。 在 cloud-config 加入 install 區塊：

#cloud-config
install:
  device: "/dev/sda"
  reboot: true
  poweroff: false
  auto: true   # 自動安裝所必需

p2p:
  network_token: ....

製作含設定的 ISO：

mkdir -p build
cd build
touch meta-data
cp -rfv cloud-config.yaml user-data
mkisofs -output ci.iso -volid cidata -joliet -rock user-data meta-data

開機時同時掛載此 ci.iso 與 Kairos ISO17。

方式 B：config URL。 開機時加入核心參數 config_url=<URL>，機器會下載設定；該值在抓取前會先以 Go template 渲染，支援 .Values.product.uuid、.Values.network 等變數17。

方式 C：以 AuroraBoot 重製 ISO（remaster）。 需 Docker：

docker run -v $PWD/cloud-config.yaml:/cloud-config.yaml \
  -v $PWD/build:/tmp/auroraboot \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --rm -ti quay.io/kairos/auroraboot:v0.27.0 \
  --set container_image=oci:$IMAGE \
  --set "disable_http_server=true" \
  --set "disable_netboot=true" \
  --cloud-config /cloud-config.yaml \
  --set "state_dir=/tmp/auroraboot"

產物位於 build/ 目錄下17。AuroraBoot 是 Kairos 官方 bootstrapper，可用單一執行檔建構開機映像（ISO、UKI、raw disk、sysext）、透過 PXE/netboot/Redfish 佈署、並以內建 dashboard 管理機群18。AuroraBoot GitHub 專案約 41 顆星18。

kairos-lab 是一支小型 Go CLI，用於本機初次體驗 Kairos，適合不常使用虛擬化軟體者19。安裝方式：

# macOS
brew tap kairos-io/kairos

5.1 cloud-config 結構#

Kairos 使用 cloud-config 格式（YAML，第一行 #cloud-config）。它支援部分標準 cloud-init 語法，並以 yip 擴充；Kairos 實際上不使用 cloud-init20。重要頂層欄位包括：users、k3s、k3s-agent、install、reset、upgrade、p2p、kubevip、stages、hostname、write_files、config_url、debug、strict20。

5.2 k3s provider 設定鍵#

k3s 區塊設定 k3s server（控制平面）實例20：

k3s-agent 區塊設定 k3s agent（工作節點）實例，鍵與 k3s 對應：k3s-agent.enabled、k3s-agent.env、k3s-agent.args、k3s-agent.replace_env、k3s-agent.replace_args、k3s-agent.embedded_registry20。

6.1 在節點上使用 kubectl#

6.2 取得 kubeconfig#

scp kairos@<node-ip>:/etc/rancher/k3s/k3s.yaml ~/.kube/config

之後需把 ~/.kube/config 中的 server 由 https://127.0.0.1:6443 改為實際節點 IP：

export KUBECONFIG=~/.kube/config

7.2 升級#

手動升級（節點上執行）：

sudo kairos-agent upgrade list-releases
sudo kairos-agent upgrade --source oci:quay.io/kairos/hadron:v0.5.1-standard-amd64-generic-v4.3.0-k3s-v1.36.4-k3s1

--source 支援 oci:（容器登錄檔）、ocifile:（docker save 的 tarball）、dir:（已解開的 rootfs）、file:（單一映像 blob）9。被動（passive）系統不需直接升級，會在主動系統重開機時自動同步9。Trusted Boot 安裝另需傳 --boot-entry <efi_file_name>9。

透過 Kubernetes 升級（推薦使用 Kairos Operator）：

helm repo add kairos-operator https://kairos-io.github.io/kairos-operator/charts
helm repo update
helm install kairos-operator kairos-operator/kairos-operator \
  --namespace kairos-operator --create-namespace

建立 NodeOpUpgrade 資源即可進行金絲雀升級：

apiVersion: operator.kairos.io/v1alpha1
kind: NodeOpUpgrade
metadata:
  name: kairos-upgrade
  namespace: default
spec:
  image: quay.io/kairos/hadron
  nodeSelector:
    matchLabels:
      kairos.io/managed: "true"
  concurrency: 1
  stopOnFailure: true
  upgradeActive: true
  upgradeRecovery: false
  force: false

  • 以 console=tty0 rd.debug rd.immucore.debug 核心參數開機以取得詳細日誌（於 GRUB 按 e 編輯 cmdline）14。

8. 批判性來源反思#

  1. 官方文件為主，社群轉述為輔。 本報告多數敘述來自 kairos.io 官方文件與 GitHub release 資產，可信度較高17。少數詳細銷售／新聞資訊（如 Hadron 的 Spectro Cloud 新聞稿）屬於行銷材料，可能帶有推廣傾向，故僅用於佐證發布時間與定位6。

  2. 文件內部不一致。 互動式安裝產生的設定檔名，官方兩份文件分別寫 /oem/90_custom.yaml 與 /oem/99_custom.yaml1314。此類版本殘留是常見現象，實務上應以節點上 kairos-agent config 與實際檔案清單為準14。

  3. 版本節奏落差。 Kairos v4.3.0 的 official ISO 資產以 Hadron v0.5.1 命名7，但 Hadron 上游已推出 v0.5.3 與 v0.6.04。不同來源對「最新 Hadron 版本」的答案不同，原因是關注對象不同（Kairos release 資產 vs. Hadron 獨立 release）。引用版本時必須明示脈絡。

  4. k3s 版本並非單一固定值。 Kairos release pipeline 會動態查詢 k3s 最新 patch，並針對最近三個 minor 版本建構映像7。因此「Kairos v4.3.0 搭哪個 k3s」沒有唯一答案，而是取決於所選 ISO 檔名。

  5. 硬體需求缺乏權威頁面。 Kairos 官方沒有正式系統需求頁，唯一具體數字來自 Quick Start 的示範情境10。這些數字為示範／VM 取向，生產環境的資源規劃仍需保守上調。

  6. 時間敏感。 k3s 本身迭代極快（截至 2026-09-30 最新穩定版為 v1.37.1+k3s1）26，Kairos 亦持續改版。本報告的版本數字在數週後可能已過時，實作前務必重新核對。
